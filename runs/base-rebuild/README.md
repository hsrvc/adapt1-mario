# The base rebuild: the zero start's rows fed again into new domains

Fed on 2026-11-15. Server build `f5e1ab8` at the start and the end of the feed. Cost: 8,512 credits for the
feed (meter). The check was not metered: 5 frozen games, about 365 queries.

The corrector run in [`../refine-2-1/`](../refine-2-1/) plays on a base called `mario-zero2r-takeoff` / `-apex`. This
folder holds how that base began: the rows of the October zero start ([`../zero-start/`](../zero-start/)), fed again in the original order.

The 8,498 rows are the 8,431 rows in the zero-start logs ([`../zero-start/`](../zero-start/)) plus 67 rows of one more episode. By our account
the October run sent that episode's rows but did not log the episode, and we rebuilt its rows with the server dump.
The server held 68 more rows than the logs (stage 5's `model-state-after-frozen-clear.json` shows 5,450 + 3,049
= 8,499). One mid-air row is not in the rebuild.

## Result

| what | value | where |
|---|---|---|
| rows fed | 5,450 takeoff + 3,048 apex = 8,498, 0 errors, live counters equal rows sent | `feed-base.jsonl.gz`, last line |
| frozen 1-1 after the feed | **2737 on 5 of 5 seeds, no flag** (one model version, the five games are identical) | `check-1-1.json` |

These rows cleared 1-1 in October (3161 × 5, on a pair that held one more mid-air row, 3,049). Fed again in November (the October logs record no server build) they do not: the two policies
play the same moves through x 1823, then differ at one mid-air choice (compare the traces in `check-1-1.json` with
the October confirm traces of the zero start's stage 5). The base reached the flag only after 1,000
more online rows (`base2/` in [`../refine-2-1/`](../refine-2-1/)).

## Files

- `rows-base.jsonl.gz`: one row per fed event, in fed order (context, move, reward, outcome, next state).
  Regenerated by an emulator replay of the October run's logged moves and checked against a server dump of the
  original events: 8,498 rows, 0 mismatches (`verify-base.json`: 8,468 rows checked against the logged
  feedback, 30 by their context only, and one episode's seed inferred). The dump and the replay script are not here.
- `config-base-takeoff.json`, `config-base-apex.json`: the two `POST /domains` bodies.
- `feed-base.jsonl.gz` + `.provenance.json`: the feed log (every row's response) and its commit and command.
- `check-1-1.json`: learner status and the 5 frozen games after the feed.

## Command

From the repo root, the key in `REI_KEY`:

```bash
gunzip -kf runs/base-rebuild/rows-base.jsonl.gz
python scripts/rebuild_domains.py --account mine --rows runs/base-rebuild/rows-base.jsonl \
  --config-dir runs/base-rebuild --which base --create --route explicit --max-credits 9500
python scripts/rebuild_check.py --account mine --takeoff-domain mario-zero2r-takeoff \
  --apex-domain mario-zero2r-apex --out artifacts/base-check      # frozen 1-1 on 5 seeds, queries only
```

## Limits

1. The rows were fed in one batch with no play in between. The October run learned them online.
2. One model version, read once. A refit needs new rows.
3. The meter counted 8,500 feedback calls for 8,498 rows. We cannot explain the 2 extra calls.
4. Session ids are redacted by key and by shape, and 64-hex strings are cut to 8 characters. `index.json` lists
   every run file with its sha256 (not this page or the index itself). Check with `python scripts/pub/verify_runs.py runs/base-rebuild`.
